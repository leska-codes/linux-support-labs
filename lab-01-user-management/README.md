# Лабораторная №1. Linux: управление пользователями и группами

**Направление:** Linux Administration / Technical Support L1/L2  
**Уровень:** Junior  
**Практическая работа:** управление учётными записями, группами и административными правами.

## 1. Постановка задачи

### Легенда

Компания ByteForge расширяет штат сотрудников. Необходимо организовать учётные записи, распределить пользователей по подразделениям и настроить административные привилегии.

Дополнительно требуется обработать инцидент безопасности: заблокировать учётную запись бывшего системного администратора и провести реорганизацию подразделений.

### Техническое задание

Создать группы:

- `backend` — backend-разработка;
- `frontend` — frontend-разработка;
- `infra` — инфраструктура;
- `analytics` — аналитика.

Создать пользователей:

- `alex_m` — backend-разработчик Алексей Морозов;
- `marina_v` — frontend-разработчик Марина Волкова;
- `denis_ops` — системный администратор Денис Орлов;
- `katya_data` — аналитик Екатерина Соколова.

Настроить основное и дополнительное членство в группах.

Предоставить `denis_ops` административные права через sudo.

Провести проверку пользователей и групп.

Заблокировать учётную запись `grisha_root`.

Перевести `marina_v` в группу `backend` и удалить ненужную группу `frontend`.

## 3. Выполнение работы

### Этап 1. Создание групп

Созданы четыре группы для подразделений компании:

`backend`, `frontend`, `infra`, `analytics`.

Проверка: просмотр записей в `/etc/group` и получение информации через `getent`.

### Этап 2. Создание пользователей

Созданы четыре учётные записи с домашними каталогами.

| Пользователь | Основная группа | Дополнительные группы |
| ------------ | --------------- | --------------------- |
| alex_m       | backend         | —                     |
| marina_v     | frontend        | —                     |
| denis_ops    | infra           | backend, sudo         |
| katya_data   | analytics       | —                     |

Для учётных записей установлены пароли. Пароли в отчёте не публикуются.

Дополнительно заполнены информационные поля пользователей с помощью `usermod -c`.

### Этап 3. Проверка учётных записей

Использованы команды `whoami`, `id`, `groups`.

Выполнена проверка членства пользователей в соответствующих группах.

Проведено переключение на пользователя `marina_v` с использованием `su -`.

### Этап 4. Инцидент безопасности

Создана тестовая учётная запись `grisha_root`, имитирующая учётную запись бывшего администратора.

Для неё выполнены следующие действия:

- Установлен пароль.
- Добавлена группа sudo.
- Выполнена блокировка пароля командой `usermod -L`.
- Проверено состояние учётной записи командой `passwd -S`.
- Проверена запись в `/etc/shadow`.

Учётная запись сохранена в системе для имитации сценария аудита.

### Этап 5. Изменение членства в группах

Для пользователя `marina_v` изменена основная группа с `frontend` на `backend`.

Использована команда `usermod -g`.

Проверены:

- основная группа пользователя;
- запись в `/etc/passwd`;
- наличие домашнего каталога.

### Этап 6. Удаление группы

Группа `frontend` удалена командой `groupdel`.

Проверено отсутствие группы через `getent group frontend`.

Пользователь `marina_v` сохранён.

### Этап 7. Финальный аудит

Выполнена итоговая проверка групп и пользователей с помощью:

- `getent group`;
- `id`;
- `passwd -S`;
- `sudo -l -U`.

## 4. Результаты

В ходе лабораторной работы отработаны операции:

- создание групп и пользователей;
- назначение основных и дополнительных групп;
- настройка административных привилегий;
- переключение между учётными записями;
- блокировка учётной записи;
- изменение основной группы пользователя;
- удаление группы без удаления пользователя;
- проверка состояния системы.
